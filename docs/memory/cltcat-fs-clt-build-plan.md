**DELETING an already-attached CLT is a multi-step teardown (learned removing asaItemSelector/asaAddItem/asaAppointmentSelector 2026-08-12):** metadata delete is blocked by a guarded chain — LightningType/LWC/Apex/Flow ← GenAiFunctionDefinition (versioned snapshots) ← GenAiPluginDefinition (topic copies) ← GenAiPlannerFunctionDef (agent versions). Order that worked: (1) user detaches actions from the current agent version + republishes; (2) **delete the OLD agent versions** that still embed snapshots (Agent Builder or API) — this is the real unlock; (3) destructive-delete genAiFunctions+LightningTypes+LWCs+test classes in one pass (commits); (4) deactivate the flows (`FlowDefinition` metadata with `<activeVersionNumber>0</activeVersionNumber>` → Obsolete); (5) delete flow *versions* via Tooling API (`sf data delete record --use-tooling-api --sobject Flow --record-id 301...`) since Metadata API throws "insufficient access rights on cross-reference id"; (6) destructive-delete the DTO Apex classes last. Deploys are ATOMIC — a single failed component rolls back the whole pass, so split into committable passes. Also delete the `CLT_Catalog_Item__c` rows (by DTO_Field_Name__c) + rebuild/redeploy UIBundle.
